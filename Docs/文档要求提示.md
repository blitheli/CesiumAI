在产品开发和软件工程中，任务要求文档的英文简称通常是 PRD（Product Requirement Document，产品需求文档）或 BRD（Business Requirement Document，业务需求文档）。在敏捷开发或针对具体技术任务时，也常被称为 Spec（Specification，技术规范/规格说明书）。 [1] 
在 [Cursor](https://cursor.com/for/documentation) 中为任务编写要求文档（PRD/Spec），最核心的高效工作流是“先对谈厘清背景，再让 AI 自动生成，最后用本地上下文约束执行”。以下是具体的操作步骤： [1, 2] 
## 🛠️ 第一步：创建文档文件
在你的项目根目录下，手动新建一个专门存放需求的文档。

* 
* 推荐在根目录或新建一个 docs/ 文件夹。
* 创建名为 requirements.md 或 prd.md 的 Markdown 文件。 [2] 
* 

## 💬 第二步：使用 Chat 对话生成框架
不要直接盲目地让 Cursor 从零写起。你可以先利用右侧的 Chat 栏（快捷键 Ctrl + L 或 Cmd + L）与 AI 进行多轮对谈，理清业务逻辑和系统边界。 [1, 2] 

   1. 输入初始 Prompt：
   
   “我准备开发一个[写下你的任务，例如：用户积分商城系统]。请扮演资深产品经理，根据我接下来的零散想法，帮我梳理并生成一份结构完整的 PRD 文件。”
   
   2. 补充细节：回答 AI 进一步追问的核心痛点、目标用户和基础功能。
   3. 一键写入文件：当 AI 输出了令你满意的需求文档草稿后，点击 AI 回复框右上角的 “Save to File” 按钮，或者直接复制内容粘贴到你刚才建立的 .md 文件中。 [3] 

## 🔗 第三步：通过 @ 符号丰富文档技术栈
在编写或修改文档时，可以使用 Cursor 强大的 @ 上下文功能来让文档更专业： [2, 4] 

* 
* 引用现有代码：在文档中写到某个功能时，输入 @Files 或 @Codebase，把现有的相关代码框架关联进去，让 AI 基于现有项目结构设计新需求。
* 集成最新外部官方文档：输入 @Docs 引入特定框架（如 React、Next.js）的最新官方规范，确保你写的要求文档没有技术代差。 [2, 4] 
* 

## 🤖 第四步：将要求文档转化为 AI 开发规则（核心技巧）
文档写完后，如何让 Cursor 之后的编程严格按照这个文档执行？

   1. 使用文件引用：后续在用 Ctrl + K（或 Cmd + K）生成代码时，第一句一定要输入 @requirements.md，并命令 AI：“请严格按照该需求文档的内容实现以下代码。”
   2. 提升为全局规则（.cursorrules）：如果你希望这个任务的要求对整个项目全局生效，可以使用命令面板（Ctrl + Shift + P / Cmd + Shift + P），输入 cursor rule 并选择 Add .cursorrules。在这个文件里直接把你的要求写进去，AI 在自动补全和重构时就不会瞎改或漏掉功能了。 [2, 5, 6] 

为了帮你快速开始，你希望我为你提供一个通用的 Markdown PRD/Spec 模版，还是针对你具体的某项开发任务直接生成第一版要求文档？
