# CesiumAI 后端说明（新手向）

本文面向第一次接触本仓库后端的开发者，说明：**API 怎么组织、Agent 怎么跑一轮对话、场景 Tools 如何产出 `sceneOps`、Skills / Astrox 如何接入、如何本地跑起来**。更完整的全栈安装与部署见仓库根目录 [README.md](../README.md)；前端侧如何应用 `sceneOps` 见 [前端说明.md](./前端说明.md)；产品决策与 MVP 规格见 [prd.md](./prd.md)。

---

## 1. 后端在做什么？

CesiumAI 后端是一个 **ASP.NET Core（.NET 10）** API：

| 能力 | 作用 |
|------|------|
| `POST /api/chat` | 同步跑一轮 LLM Agent + Tools，返回 `{ sessionId, message, sceneOps }` |
| `GET /healthz` | 健康检查（不探测 LLM / Astrox） |
| 场景 Tools | 在 C# 里组装合法 CZML / 相机 / 样式操作，写入本轮 `SceneOpCollector` |
| Astrox 客户端 | 调航天算法 WebAPI（SSO、J2、通用 Propagator 等） |
| Agent Skills | 从 content root 的 `skills/` 加载 astrox-skills，供 Agent `load_skill` |

**重要设计原则（与 PRD / 前端一致）：**

- 后端**不持有**完整场景权威；CZML 权威在前端 `CesiumSceneManager`。
- 可执行的场景变更**只**来自强类型场景 Tools 写入的 `sceneOps`，**不**从模型自然语言里正则抠 CZML。
- LLM 不手写星历 CZML；轨道计算走 Astrox / Skills，Tool 负责把结果归一成合法 packet。
- 助手回复里的 `message` 只负责说明；前端只信结构化 `sceneOps`。

一句话：**聊天是入口，Tools + Collector 才是场景变更真相；前端才是场景权威。**

### 3.1 启动时发生了什么？

`Program.cs` 在 `ValidateOnStart` 下校验：

| 配置 | 要求 |
|------|------|
| `Agent:Endpoint` | 绝对 HTTP(S) URL |
| `Agent:ApiKey` | 非空 |
| `Agent:Model` | 非空 |
| `Astrox:BaseUrl` | 绝对 HTTP(S) URL |
| `Astrox:DefaultStepSeconds` | 1–3600 |
| `Astrox:DefaultDescendingNodeLocalTime` | `[0, 24)` |
| `Skills:Path` | 相对 content root，且目录存在 |
| `ChatEndpoint:Timeout` | `> 0`（默认 120s） |
| `ReverseProxy:KnownProxies` | 可解析的 IP 列表 |

任一失败则进程**不监听**，不会拖到首个聊天请求才报错。

另外注册：

- `IAstroxClient` / `IOrbitScenarioService` / 校验器
- `AstroxRawTools`（命名 HttpClient，禁止自动重定向）
- `IAgentRuntimeFactory` → `AgentFactory`
- `IAgentTurnRunner` → `AgentRuntimeStore`（单例，进程内会话）
- `IChatService` → Scoped `ChatService`
- Development CORS：仅 `http://localhost:5173`
- `GET /healthz`

默认监听：`http://localhost:5088`（见 `Properties/launchSettings.json`）。

### 3.2 用户发一条聊天时发生了什么？

核心在 `ChatService.ChatAsync`（逻辑摘要）：

```csharp
// 伪代码；真实实现见 Services/ChatService.cs
async Task<ChatResponse> ChatAsync(ChatRequest request, CancellationToken ct)
{
    // 1. 会话：无 sessionId → 新建 GUID
    string sessionId = string.IsNullOrWhiteSpace(request.SessionId)
        ? Guid.NewGuid().ToString()
        : request.SessionId;

    // 2. 把 sceneSummary / relevantPackets / message 拼成 User prompt
    string prompt = promptBuilder.Build(request);

    // 3. 本轮专用 collector（避免串请求）
    var collector = new SceneOpCollector();

    // 4. 按 session 取 AgentRuntime，本轮绑定 collector，跑 Agent
    string message = await agentTurnRunner.RunAsync(
        sessionId, prompt, collector, ct);

    // 5. 只认 collector，不从 message 解析场景
    return new ChatResponse(sessionId, message, collector.Drain());
}
```

`ChatController` 在外层叠加：

- 客户端断开 → **499**
- 服务端 `ChatEndpoint:Timeout` 到期 → **504** + `{ error: "agent_timeout", detail: "..." }`

要点：

- **一次请求一整包响应**（非流式；对应 PRD E1）。
- 同 `sessionId` 的多轮对话共享进程内 `AgentSession`（对话记忆）；场景本身仍在前端。
- 同 session **串行**跑 turn（`SemaphoreSlim(1,1)`），避免 sink 串请求。
- Tool 失败时通常不写残缺 op；Agent 用自然语言解释错误，`sceneOps` 可能为空。

## 4. 各模块功能说明

### 4.1 `Models/ChatContracts.cs` — 前后端契约

线格式为 JSON **camelCase**，与前端 `frontend/src/contracts/chat.ts` 对齐。

**请求 `ChatRequest`**

| 字段 | 含义 |
|------|------|
| `message` | 用户自然语言（必填，非空） |
| `sessionId` | 可选；有则续聊，无则后端新建 |
| `sceneSummary` | 场景轻量摘要（必填） |
| `relevantPackets` | 可选；与本轮相关的完整 CZML 包 |

**响应 `ChatResponse`**

| 字段 | 含义 |
|------|------|
| `sessionId` | 会话 ID，前端下次带回 |
| `message` | 助手自然语言 |
| `sceneOps` | 场景操作数组（可为 `[]`） |

**`SceneSummary` / `EntitySummary`**

- `documentClock`：可选时钟摘要（`interval` / `currentTime`）
- `entities[]`：`id`、`name?`、`type`（`facility` | `satellite` | `other`）、设施经纬高、卫星 `orbitHint` 等

后端**不**根据 summary 改场景；它只进 prompt，帮助 Agent 选择 Tool / 目标 id。

### 4.2 `Models/SceneOps.cs` — 五种 SceneOp

使用 `JsonPolymorphic`，判别字段为 `"op"`：

| `op` | 类型 | 关键字段 | 谁写入 |
|------|------|----------|--------|
| `clear` | `ClearSceneOp` | 无 | `ClearScene` |
| `upsert` | `UpsertSceneOp` | `packets: JsonElement[]` | 地面站 / 卫星 Tools |
| `delete` | `DeleteSceneOp` | `ids: string[]` | `DeleteEntity` |
| `camera` | `CameraSceneOp` | `action` + 参数 | 相机 Tools |
| `style` | `StyleSceneOp` | `id`, `patch` | `UpdateEntityStyle` |

相机 `action`（`CameraAction`）：`focus`、`track`、`untrack`、`zoom`、`pan`、`rotate`、`orbitStep`、`orbitStart`、`orbitStop`。

相对 PRD §5.3 的 MVP 三元组，当前实现已扩展 **camera / style**（与前端说明一致）。

示例响应（地面站 + 对焦）：

```json
{
  "sessionId": "abc-123",
  "message": "已添加三亚站，并飞向该站。",
  "sceneOps": [
    {
      "op": "upsert",
      "packets": [
        {
          "id": "sanya",
          "name": "三亚",
          "position": {
            "cartographicDegrees": [109.5, 18.2, 50]
          },
          "point": { "pixelSize": 10, "color": { "rgba": [255, 80, 80, 255] } },
          "label": { "text": "三亚", "show": true },
          "model": { "gltf": "/models/facility.glb", "minimumPixelSize": 64 }
        }
      ]
    },
    {
      "op": "camera",
      "action": "focus",
      "targetId": "sanya",
      "distanceMeters": 800000,
      "pitchDegrees": -35
    }
  ]
}
```

### 4.3 `Controllers/ChatController.cs` — HTTP 边界

- 路由：`[Route("api/chat")]` + `[HttpPost]`
- 链接 `RequestAborted` 与服务器超时 CTS
- 成功：`200` + `ChatResponse`
- 模型绑定失败：框架默认 `400`
- 超时 / 取消：见上文 504 / 499

Controller **很薄**：不做 Agent 组装、不碰 Astrox。

### 4.4 `Services/ChatService.cs` — 编排层

对应 PRD §7.1 主流程，职责边界：

| 负责 | 不负责 |
|------|--------|
| 解析/创建 `sessionId` | 持有完整 CZML |
| 组 prompt、跑 Agent turn | 直接改前端 Viewer |
| 本轮 `SceneOpCollector` 生命周期 | 从文本抠场景 JSON |
| 打包 `ChatResponse` | 持久化会话到磁盘 |

### 4.5 `Services/ScenePromptBuilder.cs` — Prompt 形状

把请求序列化为三段文本，交给 Agent 当本轮 User 消息：

```text
[SCENE_SUMMARY]
{...camelCase JSON...}

[RELEVANT_CZML_PACKETS]
[...]

[USER]
用户原话
```

这样模型能看到「球上有什么」和「本轮相关 packet」，但**写场景仍只能走 Tools**。

### 4.6 `Services/SceneOpCollector` / `TurnSceneOpSink` — 只信 Collector

- `SceneOpCollector`：线程安全 `Add` / `Drain`（Drain 后清空）
- `TurnSceneOpSink`：挂在 `AgentRuntime` 上；**仅在本轮**把 `Current` 设为该请求的 collector
- Tools 通过 `ISceneOpSink.Add` 写 op；无活跃 turn 时 `Add` 会抛错

这是「collector 不串请求」的实现（PRD 风险对策）。

### 4.7 `Services/AgentFactory.cs` — SpaceAgent 组装

每个新 `sessionId` 创建一套：

1. `TurnSceneOpSink` + `SceneTools`（闭包到该 sink）
2. Tools 列表（场景 + 相机 + 样式 + 传播 + 受限 HTTP）
3. `OpenAIClient(ApiKey, Endpoint).GetChatClient(Model).AsAIAgent(...)`
4. `AIContextProviders = [ AgentSkillsProvider(skills/) ]`
5. `CreateSessionAsync` → `AgentRuntime`

Skills Provider 选项（当前）：

- `DisableLoadSkillApproval = true`
- `DisableReadSkillResourceApproval = true`
- `DisableRunSkillScriptApproval = false`（脚本仍需审批策略约束）

### 4.8 `Services/AgentRuntimeStore.cs` — 会话存储

| 项 | 策略 |
|----|------|
| 存储 | `ConcurrentDictionary<sessionId, Lazy<Task<AgentRuntime>>>` |
| 内容 | `AIAgent` + `AgentSession` + `TurnSceneOpSink` + turn 信号量 |
| 过期 | MVP 不做清理（开发期重启即丢） |
| 场景 | **不**进 Session；场景在前端 |
| 并发 | 同 session 串行 turn |

### 4.9 `Services/AgentInstructions.cs` — 系统指令（摘要）

1. 场景 / 样式 / 相机变更必须调对应 Tool，禁止只口头声称已改
2. 禁止在助手文本里放可执行 CZML
3. 纯问答不调场景 Tools
4. 非 `AddSatelliteJ2` 快捷路径：先 `load_skill`，再 `PropagateAndAddSatellite`；大 Position 不在模型与工具结果间往返
5. 「添加 ISS」默认流程：加载 SGP4/TLE skill → 受限 `HttpGet` 查 NORAD 25544 TLE → `PropagateIssAndAddSatellite`；TLE 失败则不写 op
6. 简洁中文回答

### 4.10 `Tools/SceneTools.cs` — 场景 Tools 一览

| Tool | 作用 | 写入的 SceneOp |
|------|------|----------------|
| `ClearScene` | 清空业务实体 | `clear` |
| `UpsertFacility` | 本地拼地面站 CZML（point/label/model） | `upsert` |
| `DeleteEntity` | 按 id 删除（忽略 `document`） | `delete` |
| `AddSatelliteJ2` | SSO wizard + J2 递推 → 卫星 packet | `upsert` |
| `PropagateAndAddSatellite` | 通用 `/Propagator/*` + 校验 Position | `upsert` |
| `PropagateIssAndAddSatellite` | 注入 Start/Stop/Step 后走 SGP4 | `upsert` |
| `AddSatelliteFromPositions` | 已有可信 Position JSON → packet | `upsert` |
| `FocusEntity` | 飞到实体 | `camera/focus` |
| `TrackEntity` / `StopTracking` | 跟踪 / 取消 | `camera/track` / `untrack` |
| `AdjustCamera` | `zoom` / `pan` / `rotate` | `camera/...` |
| `OrbitEntity` / `StopOrbit` | `step` / `start` / 停止环绕 | `camera/orbit*` |
| `UpdateEntityStyle` | 白名单样式 patch | `style` |

约束（工具层强制）：

- id 非空；实体目标禁止使用 `document`
- 经度 `[-180,180]`、纬度 `[-90,90]`；数值拒绝 NaN/Infinity
- 卫星 availability 窗口 ≤ 24h；`hours` / `stepSeconds` 有上下界
- 样式经 `SceneStyleValidator`；失败不写 op
- 传播类 Tool **不向模型回传大型 Position**，只返回短确认字符串

### 4.11 `Astrox/` — 算法与 CZML 归一化

**`AstroxClient`**

- `CreateSsoAsync` → `POST /OrbitWizard/SSO`
- `PropagateJ2Async` → `POST /Propagator/J2`
- `PropagateAsync` → `POST /Propagator/{name}`（路径规范化，响应体大小上限）
- 校验 Astrox 成功信封（`IsSuccess` 等）；失败抛可读错误

**`OrbitScenarioService`**

- `CreateSsoJ2PacketAsync`：SSO 要素 → J2 星历 → `BuildSatellitePacket`
- `CreatePacketFromPropagationAsync` / `CreatePacketFromPositions`：校验 Position 后同样建包
- 卫星 packet 典型字段：`id`/`name`/`availability`/`position`/`point`/`path`/`model`（`/models/satellite.glb`）/`properties.orbitHint`

**校验器**

- `PropagationRequestValidator`：发往 Astrox 前核对请求根 `Start`/`Stop`/`Step` 与 Tool 声明窗口一致
- `CzmlPositionValidator`：Position 结构与时间窗合法性

### 4.12 `Tools/AstroxRawTools.cs` — 探索用 HTTP

- 仅允许 **根相对路径**（以单个 `/` 开头），且解析后必须与 `Astrox:BaseUrl` **同 origin**
- 禁止 `\`、`..`、过度 URL 解码绕过
- `AllowAutoRedirect = false`
- 用途：查 TLE、读 API 文档式探索；**不是**写场景的主路径（写场景走 SceneTools）

## 5. 环境变量与密钥（后端）

| 配置项 | 环境变量 | 是否必需 | 说明 |
|--------|----------|----------|------|
| `Agent:ApiKey` | `Agent__ApiKey` | 真实对话必需 | 切勿写入前端 `VITE_*` |
| `Agent:Endpoint` | `Agent__Endpoint` | 有默认 | OpenAI 兼容基址 |
| `Agent:Model` | `Agent__Model` | 有默认 | 如 `kimi-k2.6` |
| `Astrox:BaseUrl` | `Astrox__BaseUrl` | 有默认 | Astrox WebAPI |
| `Skills:Path` | `Skills__Path` | 有默认 `skills` | 必须相对 content root |
| `ChatEndpoint:Timeout` | `ChatEndpoint__Timeout` | 有默认 120s | 整请求超时 |

推荐本地：

```bash
dotnet user-secrets set "Agent:ApiKey" "<your-key>" --project backend/CesiumAI.Api
```

占位 key 足以通过启动校验并访问 `/healthz`；真实 `POST /api/chat` 需要有效 key，否则 LLM 侧会鉴权失败（常见表现为 HTTP 500 / 上游 401）。

## 6. 运行步骤（尽量详细）

### 6.1 前置条件

- .NET **10** SDK
- 已初始化 `backend/astrox-skills` submodule
- 可访问的 OpenAI 兼容模型（真实对话）
- 可访问的 Astrox WebAPI（建星 / ISS / 通用传播）

仅跑 `dotnet test` 时，多数用例用 stub，**不需要** live LLM / Astrox。

### 6.2 初始化 Skills

```bash
# 仓库根目录
git submodule update --init --recursive
```

### 6.3 配置 ApiKey

```bash
dotnet user-secrets set "Agent:ApiKey" "<your-key>" --project backend/CesiumAI.Api
```

可选覆盖：

## 8. 示例：后端侧理解「只信 Collector」

即使 Agent 在 `message` 里胡写一段 CZML，只要没调用场景 Tool，响应仍是：

```json
{
  "sessionId": "...",
  "message": "……（可能含误导性文字）……",
  "sceneOps": []
}
```

前端不会执行那段文字。正确路径是 Tool → Collector：

```csharp
// SceneTools 内部（示意）
_sceneOpSink.Add(new ClearSceneOp());
// ...
_sceneOpSink.Add(new UpsertSceneOp([packet]));
// ChatService 末尾：
return new ChatResponse(sessionId, message, collector.Drain());
```

卫星路径（J2 快捷）：

```text
AddSatelliteJ2
  → OrbitScenarioService.CreateSsoJ2PacketAsync
       → Astrox /OrbitWizard/SSO
       → Astrox /Propagator/J2
       → BuildSatellitePacket(position, path, model, ...)
  → UpsertSceneOp([packet])
  → 返回短字符串给模型（无大型 Position）
```

## 10. 常见问题

### Q1：启动就失败，提示 Skills directory 不存在？

先 `git submodule update --init --recursive`，再 `dotnet build` / `dotnet run`，让 csproj 同步到 `CesiumAI.Api/skills/`。若 User Secrets 里残留旧绝对路径或 `../astrox-skills/skills`，删掉该覆盖，改用默认相对路径 `skills`。

### Q2：`/healthz` 正常，但聊天 500 / 鉴权错误？

占位 key 只够启动。检查 `Agent:ApiKey`（User Secrets 或 `Agent__ApiKey`）是否为模型服务接受的真实 key，以及 `Agent:Endpoint` / `Model` 是否匹配。

### Q3：为什么有助手回复，但 `sceneOps` 是 `[]`？

- 纯问答（指令要求不调场景 Tool）
- Tool 调用失败（Astrox 超时 / 校验失败），只写了错误说明
- 模型未按 Instructions 调 Tool（只信 collector，不会从文本补救）

### Q4：和 PRD 里「只有 clear/upsert/delete」不一致？

文档以**当前代码**为准。已扩展 `camera`、`style` 及更多建星 / ISS Tools；PRD 仍是 MVP 决策基线。

### Q5：为什么不同 session 之间对话记不住？

Session 存在进程内字典；新 `sessionId`、进程重启、或另一台机器都没有共享记忆。场景状态本就在前端，刷新页面不会丢球上实体，但会丢 Agent 对话上下文（前端通常也会丢 `sessionId`）。

### Q6：能流式返回吗？

当前实现是同步整包（E1）。PRD 后续项 E2 提到 SSE 式先推 token、最后推 `scene_ops`，**尚未**实现。

### Q7：Astrox 很慢怎么办？

整请求受 `ChatEndpoint:Timeout`（默认 120s）约束，超时返回 504。前端 loading 覆盖等待期；**不要**自动重试改场景请求，以免重复 upsert。
