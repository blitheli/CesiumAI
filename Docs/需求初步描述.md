我想开发的是一个采用Cesium.js作为基础框架的航天任务智能设计和可视化网站。

前端页面采用Cesium.js实现三维地球和空间卫星的轨迹动态可视化，采用React(Vite)开发实现。

后端打算使用Asp.net core方法开发航天任务分析智能体（后面简称“agent")，使用Mircosoft Agent Framework开发。

前端页面除了Cesium的Viewer视图窗口，还有一个用户和agent聊天的窗口，可参考我图片(Docs/cesium-sandcastle-copolit.png)，具体文档可参考：Docs/cesium-copolit.md） 。但是和这个有所不同，我不需要沙盒机制，我需要是一个实际的产品页面。

前端Cesium添加点,轨迹等通常使用Entity创建，我个人更倾向使用czml文件方式作为一个场景，这样，场景内的所有对象（点，飞行器等等）都可以控制。

前端页面典型的用户场景如下：

- 清空当前场景
- 在当前场景下，改变地面站sanya的经纬度(改变czml文件中的sanya entity的经纬高数据)
- 添加一个地面站，经纬度是-100,30.2,10。即在原先加载的czml文件中的datasources增加新的entity 点
- 添加一个卫星，使用J2摄动递推，轨道参数为900km SSO轨道。后台调用工具或skill获取900km SSO的一天内的位置速度,czml文件中positions格式。前端加载完成后显示卫星的动态轨迹。

后端的功能

- 我已经有了一个航天任务分析的算法相关skills库，agent可以使用这个skills，实现诸如”J2摄动的卫星的轨道积分，获得czml格式的positions数据(cartesianVelocity属性)。
- 可以在agent端扩充其它航天任务相关的tools和skills。

我的总体想法：

- 使用一个czml文件作为单个场景的管理。所有的对象都在这个czml文件中，实现entity的添加和删除等。
- agent尽量返回czml格式的数据，前端进行加载，更新viewer的显示。
