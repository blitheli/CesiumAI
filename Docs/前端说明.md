# CesiumAI 前端说明（新手向）

本文面向第一次接触本仓库前端的开发者，说明：**页面怎么组织、数据怎么流动、场景怎么更新、如何本地跑起来**。更完整的全栈安装与部署见仓库根目录 [README.md](../README.md)。

---

## 1. 前端在做什么？

CesiumAI 前端是一个 **React + Cesium** 单页应用：

| 区域 | 作用 |
|------|------|
| 左侧/主区三维球 | Cesium `Viewer`，用 **CZML** 显示地面站、卫星等实体 |
| 右侧聊天面板 | 用户用自然语言描述想做的事 |

**重要设计原则（和 Cesium Sandcastle Copilot 不同）：**

- 前端**不执行** Agent 返回的任意 JavaScript。
- Agent / 后端只返回结构化 **`sceneOps`**（场景操作列表）。
- 前端用本地固定逻辑解释这些操作：改内存中的 CZML 文档，再同步到 `CzmlDataSource` / 相机控制器。
- 助手回复里的自然语言只负责说明；**可执行的场景变更只来自 `sceneOps`**。

一句话：**聊天是入口，CZML + SceneOp 才是场景真相。**

## 3. 整体架构与一次对话的数据流

```text
┌─────────────┐     用户输入      ┌──────────────┐
│  ChatPanel  │ ───────────────► │     App      │
└─────────────┘                  └──────┬───────┘
                                        │
                    组装 ChatRequest     │
                    （message + sessionId│
                     + sceneSummary      │
                     + relevantPackets） │
                                        ▼
                                 ┌─────────────┐
                                 │  postChat   │  POST /api/chat
                                 └──────┬──────┘
                                        │
                                        ▼
                                 ┌─────────────┐
                                 │  后端 Agent │  （本文不展开）
                                 └──────┬──────┘
                                        │
                         ChatResponse   │
                    { sessionId,        │
                      message,          │
                      sceneOps[] }      │
                                        ▼
                                 ┌──────────────────┐
                                 │ CesiumSceneManager│
                                 │  applySceneOps()  │
                                 └────────┬─────────┘
                        ┌─────────────────┼─────────────────┐
                        ▼                 ▼                 ▼
                 sceneDocument      CzmlDataSource     CameraController
                 （内存 CZML）       （球上实体）        （flyTo/track…）
```

### 3.1 启动时发生了什么？

`main.tsx` 里创建**唯一**的 `CesiumSceneManager`，注入 `App`：

```tsx
// frontend/src/main.tsx（示意）
import { createRoot } from "react-dom/client";
import { App } from "./app/App";
import { CesiumSceneManager } from "./scene/CesiumSceneManager";

const sceneManager = new CesiumSceneManager();
createRoot(document.getElementById("root")!).render(
  <App sceneManager={sceneManager} />,
);
```

`App` 渲染：

- `ViewerHost`：挂载 Cesium，调用 `sceneManager.initialize(viewer)`
- `ChatPanel`：绑定 `onSend={handleSend}`

初始化时 SceneManager 会加载「空文档」（只有 `id: "document"` 的时钟 packet），球上暂时没有业务实体。

### 3.2 用户点「发送」时发生了什么？

核心在 `App.handleSend`（逻辑摘要）：

```ts
// 伪代码，便于理解；真实实现见 frontend/src/app/App.tsx
async function handleSend(text: string) {
  // 1. UI：追加用户消息，进入 loading
  addMessage("user", text);

  // 2. 从当前场景生成摘要（给 Agent 看「球上有什么」）
  const summary = sceneManager.buildSummary();

  // 3. 根据用户文本 + 当前选中实体，推断相关 entity id
  const relevantIds = inferRelevantEntityIds(
    text,
    summary,
    sceneManager.getSelectedEntityIds(),
  );

  // 4. 取出这些实体的完整 CZML packet（缩小上下文体积）
  const relevantPackets = sceneManager.pickRelevantPackets(relevantIds);

  // 5. POST 后端
  const response = await postChat(
    {
      message: text,
      sessionId,           // 首次可为 null，后端会发新 sessionId
      sceneSummary: summary,
      relevantPackets,
    },
    abortSignal,
  );

  // 6. 更新会话与助手文案
  setSessionId(response.sessionId);
  addMessage("assistant", response.message);

  // 7. 应用结构化场景操作（真正改球）
  await sceneManager.applySceneOps(response.sceneOps);
}
```

要点：

- **一次请求一整包响应**（非流式）；见 `api/chat.ts`。
- 请求可被 `AbortController` 取消（组件卸载时会 abort）。
- 若 HTTP 失败或 `sceneOps` 校验失败，只显示错误，**不会**半套应用畸形 ops。

## 4. 各模块功能说明

### 4.1 `contracts/chat.ts` — 前后端契约

定义线格式（JSON camelCase）类型，前后端应对齐：

**请求 `ChatRequest`**

| 字段 | 含义 |
|------|------|
| `message` | 用户自然语言 |
| `sessionId` | 可选；有则续聊，无则后端新建 |
| `sceneSummary` | 场景轻量摘要（实体 id/类型/大致位置等） |
| `relevantPackets` | 可选；与本轮相关的完整 CZML 包 |

**响应 `ChatResponse`**

| 字段 | 含义 |
|------|------|
| `sessionId` | 会话 ID，前端要存起来下次带回 |
| `message` | 助手自然语言 |
| `sceneOps` | 场景操作数组（可为 `[]`） |

**`SceneOp` 五种（白名单）**

| `op` | 作用 | 关键字段 |
|------|------|----------|
| `clear` | 清空业务实体，回到空文档 | 无 |
| `upsert` | 新增或按 `id` 覆盖 CZML packet | `packets: CzmlPacket[]` |
| `delete` | 按 id 删除实体 | `ids: string[]` |
| `style` | 对已有实体做视觉补丁 | `id`, `patch` |
| `camera` | 相机动作 | `action` + 参数（见下） |

相机 `action` 包括：`focus`、`track`、`untrack`、`zoom`、`pan`、`rotate`、`orbitStep`、`orbitStart`、`orbitStop`。

示例（地面站 upsert + 飞过去）：

```json
{
  "sessionId": "abc-123",
  "message": "已添加三亚站，并飞向该站。",
  "sceneOps": [
    {
      "op": "upsert",
      "packets": [
        {
          "id": "sanya",
          "name": "三亚",
          "position": {
            "cartographicDegrees": [109.5, 18.2, 50]
          },
          "point": {
            "pixelSize": 12,
            "color": { "rgba": [255, 200, 0, 255] }
          }
        }
      ]
    },
    {
      "op": "camera",
      "action": "focus",
      "targetId": "sanya",
      "distanceMeters": 800000,
      "headingDegrees": 0,
      "pitchDegrees": -35
    }
  ]
}
```

### 4.2 `api/chat.ts` — HTTP 客户端

- `postChat(request, signal)`：`POST ${VITE_API_BASE_URL ?? ""}/api/chat`
- 失败时尽量读响应体里的 `detail`
- 成功后用 `isChatResponse` 校验；其中 `sceneOps` 走 `isSceneOpArray`

开发时通常：

```text
VITE_API_BASE_URL=http://localhost:5088
```

未设置时请求同源 `/api/chat`（适合生产反代同源部署）。

### 4.3 `api/sceneOpsRuntime.ts` — 运行时护栏

TypeScript 类型在编译期有效；**运行时**还要对后端 JSON 做白名单校验：

- 未知 `op` → 整包拒绝
- `camera` 缺必填字段 / 数值非有限 → 拒绝
- 防止畸形数据进入 `applySceneOps`

这是安全边界的一部分：前端只接受约定好的结构化操作。

### 4.4 `components/ChatPanel.tsx` — 聊天 UI

纯展示与输入，**不直接调 API**：

- 展示 `messages`（user / assistant）
- `loading` / `error` 反馈
- `onSend(text)` 交给 `App`
- Enter 发送，Shift+Enter 换行；兼容中文输入法 composing

### 4.5 `components/ViewerHost.tsx` — Cesium 宿主

职责边界很清晰：

1. 创建 `Viewer`（timeline、infoBox、selectionIndicator 等已打开）
2. 可选设置 `Ion.defaultAccessToken`（`VITE_CESIUM_ION_TOKEN`）
3. 监听 `selectedEntityChanged` → `sceneManager.setSelectedEntityIds`
4. `sceneManager.initialize(viewer)`
5. 卸载时：`destroy()` Viewer 与 SceneManager

**不负责**解析聊天、应用 ops；那些在 `App` + `CesiumSceneManager`。

### 4.6 `scene/CesiumSceneManager.ts` — 场景中枢

这是前端最核心的类，建议重点读。

维护：

| 状态 | 说明 |
|------|------|
| `sceneDocument` | 内存中的 CZML packet 数组（含 `document`） |
| `CzmlDataSource` | 挂到 Viewer 上的数据源 |
| `CameraController` | 解释 `camera` ops |
| 操作队列 | `applySceneOps` 串行执行，避免并发打乱文档 |

主要 API：

| 方法 | 作用 |
|------|------|
| `initialize(viewer)` | 挂 DataSource、相机控制器，加载空文档 |
| `applySceneOps(ops)` | 按序应用 clear/upsert/delete/style/camera |
| `buildSummary()` | 生成发给后端的场景摘要 |
| `pickRelevantPackets(ids)` | 按 id 取完整 packet |
| `setSelectedEntityIds` / `getSelectedEntityIds` | 与 Viewer 选中同步 |
| `getSceneDiagnostics()` | 只读诊断（测试开关下可用） |
| `destroy()` | 释放资源 |

`upsert` 失败时会尝试 **回滚** 到先前文档并恢复时钟/跟踪，避免球上状态与内存文档长期不一致。

### 4.7 `scene/sceneDocument.ts` — 纯文档归约

`reduceSceneDocument(current, ops, emptyDocument)`：

- **不碰 Cesium**，只改 packet 数组
- `clear` → 换成空文档
- `upsert` → 按 id 替换或追加（忽略业务侧对 `document` 的 upsert）
- `delete` → 删实体，保留 `document`
- `style` → 调 `sceneStyle.applyStylePatch`
- 遇到 `camera` 会抛错（相机不改文档，由 SceneManager 单独交给相机控制器）

这种拆分便于单测：文档逻辑与 WebGL 解耦。

### 4.8 `scene/summary.ts` — 摘要与相关实体

- `buildSceneSummary`：把 document 变成轻量 `SceneSummary`（设施带经纬高，卫星带 orbitHint 等）
- `inferRelevantEntityIds`：根据用户文本、摘要、当前选中，猜本轮相关 id
- 目的：请求体不要塞全量 CZML，只带「可能用到的」packets

### 4.9 `scene/emptyDocument.ts` — 空场景模板

仅一个 `document` packet + 24 小时时钟窗口，例如：

```ts
{
  id: "document",
  name: "CesiumAI Scene",
  version: "1.0",
  clock: {
    interval: `${startIso}/${stopIso}`,
    currentTime: startIso,
    multiplier: 60,
  },
}
```

### 4.10 `scene/CesiumCameraController.ts` — 相机

解释 `SceneOp` 中 `op: "camera"` 的各种 `action`：

- `focus`：飞到目标实体（内部会用 Viewer 的 flyTo 等）
- `track` / `untrack`：跟踪实体
- `zoom` / `pan` / `rotate`：相对调整
- `orbitStart` / `orbitStep` / `orbitStop`：环绕

并处理实体被 upsert 替换时的跟踪重绑、场景 clear 时清状态等边界情况。

### 4.11 `app/App.tsx` — 应用编排层

把 UI 状态与场景/网络粘在一起：

- 消息列表、`sessionId`、`loading`、`error`
- 可注入 `chatClient` / `ViewerComponent`（方便测试 mock）
- 可选 `VITE_ENABLE_TEST_DIAGNOSTICS=true`：暴露场景诊断 UI / `window.__CESIUM_AI_READ_DIAGNOSTICS__`

布局：`app-shell` = 左侧 `viewer-pane` + 右侧 `ChatPanel`。

## 6. 运行步骤（尽量详细）

### 6.1 前置条件

- Node.js **20.19+** 或 **22.12+**
- npm
- 若要真实对话：还需 .NET 10、配置好的后端（见 README：User Secrets 中的 `Agent:ApiKey`、skills submodule 等）

仅看 UI / 跑前端单元测试 / e2e（mock API）时，**可以不启后端**。

### 6.2 安装前端依赖

在仓库根目录：

```bash
cd frontend
npm ci
# 若要跑 e2e，再安装浏览器：
npx playwright install chromium
cd ..
```

### 6.3 方式 A：一键启动前后端（推荐）

```bash
# 仓库根目录
npm install
npm run dev
```

会同时启动：

| 服务 | 地址 |
|------|------|
| 后端 API | http://localhost:5088 |
| 前端 Vite | http://localhost:5173（已设 `VITE_API_BASE_URL=http://localhost:5088`） |

浏览器打开：**http://localhost:5173**

停止：在该终端 `Ctrl+C`。

真实聊天前请确认：

1. `git submodule update --init --recursive`（astrox-skills）
2. `dotnet user-secrets set "Agent:ApiKey" "<your-key>" --project backend/CesiumAI.Api`
3. 后端 `/healthz` 可访问（可用占位 key 启动健康检查；对话需要有效 key）

### 6.5 方式 C：只跑前端（无后端）

```bash
cd frontend

```

页面能打开，但发送聊天会因连不上 `/api/chat` 失败。可用于调 UI、看空球、改样式。

```bash

```

生产构建通常**不**设置 `VITE_API_BASE_URL`，由网关把 `/api/` 反代到后端（见 README「生产部署」）。`dist/cesium` 是 Cesium 静态资源，部署时必须一起拷贝。

### 6.7 建议的第一次上手操作

1. 按方式 A 启动，打开 http://localhost:5173

4. 在球上点击实体 → 选中信息会参与下一轮 `relevantPackets` 推断  
5. 打开浏览器开发者工具 Network，查看 `POST /api/chat` 的请求/响应 JSON，对照本文第 4.1 节

## 8. 示例：前端侧模拟一轮「应用 sceneOps」

下面示例帮助理解「不经过后端时，场景层怎么工作」。真实产品路径仍是 `postChat` → `applySceneOps`。

```ts
import { CesiumSceneManager } from "./scene/CesiumSceneManager";
import type { SceneOp } from "./contracts/chat";

const manager = new CesiumSceneManager();
// 实际应用中由 ViewerHost 调用 initialize(viewer)

const ops: SceneOp[] = [
  { op: "clear" },
  {
    op: "upsert",
    packets: [
      {
        id: "sanya",
        name: "三亚",
        position: { cartographicDegrees: [109.5, 18.2, 50] },
        point: { pixelSize: 14, color: { rgba: [0, 255, 255, 255] } },
      },
    ],
  },
  {
    op: "camera",
    action: "focus",
    targetId: "sanya",
    distanceMeters: 1_000_000,
    pitchDegrees: -40,
  },
];

await manager.applySceneOps(ops);

// 发给后端的摘要长什么样？
console.log(manager.buildSummary());
// → { entities: [{ id: "sanya", name: "三亚", type: "facility", lon, lat, alt }], ... }
```

手动调用 `postChat`（例如在控制台调试脚本中）：

```ts
import { postChat } from "./api/chat";

const response = await postChat(
  {
    message: "把 sanya 高度改为 100",

      entities: [
        {
          id: "sanya",
          name: "三亚",
          type: "facility",
          lon: 109.5,
          lat: 18.2,
          alt: 50,
        },
      ],
    },

      {
        id: "sanya",
```

## 9. 常见问题

### Q1：为什么球没变，但聊天有回复？

- 看 Network 里响应的 `sceneOps` 是否为 `[]`
- 后端可能只回答了文字、工具未产出 ops
- 前端校验失败会抛 `Invalid chat response: malformed sceneOps`，页面显示错误而不会应用

### Q2：和 Sandcastle Copilot 差在哪？

| | Sandcastle Copilot | CesiumAI 前端 |
|--|-------------------|---------------|
| Agent 产出 | 改编辑器 JS | 结构化 `sceneOps` |
| 执行环境 | iframe 沙盒跑用户代码 | 固定 TypeScript 解释器 |
| 场景载体 | 任意脚本 | 内存 CZML + DataSource |

### Q3：能做信息浮层 / 导览 UI 吗？

可以，且**不必**执行 Agent 下发的 JS。常见做法是扩展新的 SceneOp（如 `tour`）或前端内置 Tour 组件，用结构化步骤 + 已有 `camera.focus`。当前版本**尚未**内置自定义 DOM 导览浮层；仅有 Cesium 原生 InfoBox（点选实体时）。

### Q4：是流式聊天吗？

否。当前是 POST 整包请求/响应。POST **本身**不阻止流式，但现有协议与实现未做 SSE/分块。详见对话中的架构说明。

### Q5：Cesium 资源 404？

Vite 通过 `vite-plugin-static-copy` 把 Cesium 的 Assets/Workers 等拷到 `/cesium`，并定义 `CESIUM_BASE_URL`。开发与 `dist` 部署都要保证该路径可访问。
